# sxz v4 评分实现对齐

2026-09-21。按项目负责人要求，公开 `evaluation/` 改用生成论文结果的 sxz v4
提示词和评分规则。此前报告中“二分类论文提示词是当前评分标准”的说明为历史状态；
当前规则和命令以 [evaluation/README.md](../../../evaluation/README.md) 为准。

## 实现

- `evaluation/sxz_v4.py` 逐字移植原脚本的 51 个规则常量/函数，权重位置改为当前
  checkout 下的 `models/Qwen3.6-27B`。不导入或改写协作目录，不复制原输出位置。
- 提示词保存原始三分类 JUDGE_RULES，并保留原脚本完整提示构造；Dataset 字段也一致。
- 原始预测恢复、字段优先级、空白处理、金标来源、证据评分先后顺序、技术失败计分、
  CORRECT/PARTIAL/WRONG 标签解释、固定分母和普通题拆分均使用同一函数。
- 新入口只读结果和源缓存；核验缓存输入绑定及 raw 标签一致性，缺少判定就失败。
  新 GPU 运行使用独立缓存并绑定当前权重、依赖和源代码，不混入原实验缓存。
- `reproduce.py` 复用同一入口，仅加强退出状态：已计算的论文单元格有差异即返回 2。
- 旧二分类诊断入口给出明确迁移提示，不会在加载 GPU 后才发现协议/缓存不匹配。
  内部二分类诊断固定读取保留的 `paper_semantic_judge.txt`，不当作 v4 论文评分。

## 真实文件全量验证

使用当前 `data/results/` 下 11 模型 × 5 个结果文件，共 24,148 条现存预测记录；
各模型的固定分母仍为 2,200。使用原始 21,050 条 Judge 缓存，以及原始学科清单。
从预测字段开始恢复、匹配缓存、计算证据指标并汇总，未读取历史汇总值作为评分输入。
历史 CSV 仅用于评分后的数值对照。

| 检查 | 结果 |
| --- | --- |
| 历史 77 行汇总的全部数值字段 | **1,540/1,540 一致**，差异容限 1e-12 |
| 论文 Table 2 | **99/99 显示值一致** |
| 论文 Table 3 | **98/99 显示值一致**，88 个学科值全部一致 |
| Qwen3-VL-8B All | 1503/2200 = **68.31818181818181%** |
| Qwen3-VL-8B E-F1 / A-Pages | **40.664217879496846% / 8.442272727272726** |
| 新 GPU Judge 调用 | **0**；这是原实验缓存回放 |
| 正式四文件 QA | 全部与既有 release manifest SHA-256 相符 |

唯一论文差异为 Claude Table 3 All：按该表原学科清单汇总为
1497/2200 = **68.04545454545455%**，论文用了 Table 2 的 1525/2200 = **69.32%**。
28 个正确项不在学科清单内。没有更改表格、题目集合或标签来消除这 1.27 个百分点差异。

源代码一致性测试检查移植函数逐字哈希，并在本机只读编译原 `sxz` 脚本，逐题比较两端
计算结果。手算测试覆盖 PARTIAL 零分、错误答案仍获证据分、缺金标证据不获空集合分、
固定分母、缓存缺失/篡改、学科集合及只读路径边界。相关测试 **68 项通过**；文档同步后，全仓 `python -m pytest -q` **553 项通过**。
